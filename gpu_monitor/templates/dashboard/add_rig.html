Add New Rig

Follow these steps on each GPU rig you want to monitor. The agent collects hardware metrics every 60 seconds via cron and sends them to this server.

1

Transfer Agent Files to the Rig

Clone the repository on the rig and navigate to the agent directory.

cd ~
mkdir -p workspace
cd workspace
git clone https://github.com/dawmro/GPU-Rig-Monitoring-Platform.git
cd GPU-Rig-Monitoring-Platform/agent

Suggested path: ~/workspace/GPU-Rig-Monitoring-Platform/agent

2

Run the Installer

The installer creates the monitoring user, directories, virtualenv, config, sudoers, cron job, and auto-update check.

# Ubuntu 20.04+ / Debian 11+ (Python 3.10+)
sudo apt update && sudo apt install python3.10-venv -y && sudo rm -rf /opt/monitoring-agent/venv && sudo chmod +x install.sh && sudo ./install.sh
Older Python versions (3.8/3.9) — click to expand 
sudo apt update && sudo apt install python3.8-venv -y && sudo apt install -y python3-venv && sudo rm -rf /opt/monitoring-agent/venv && sudo chmod +x install.sh && sudo ./install.sh

Note: Must be run with bash, not sh. Uses set -o pipefail.

Step What It Does
1Creates monitoring-agent system user (no-login shell)
2Creates directories: /opt/monitoring-agent/, /etc/monitoring-agent/, /var/log/monitoring-agent/
3Creates Python virtualenv; installs psutil, py-cpuinfo, requests, pyyaml, pynvml; Docker via CLI (no Python SDK)
4Copies run.py; creates config template at /etc/monitoring-agent/config.yaml
5Configures sudoers (/etc/sudoers.d/monitoring-agent) for SMART, NVMe, journalctl, docker (read-only, passwordless)
6Creates cron job — runs every 60s with flock to prevent overlaps
7Schedules daily auto-update check (random time to avoid thundering herd)
3

Configure the Agent

Edit the config file on the rig and add your API key.

nano /etc/monitoring-agent/config.yaml
rig_uuid: "auto"
rig_name: "gpu-server-01"
api_key: "PASTE_YOUR_API_KEY_HERE"
server_endpoint: "https://monitor.example.com"
expected_gpu_count: 0
collection_timeout_s: 45
retry_attempts: 3
debug_mode: false
Create API Key in Dashboard ← Click to open API Keys page
  • rig_uuid: "auto" — auto-generates permanent UUID on first run
  • rig_name: Initial name (used once at registration). Leave empty to use hostname. Rename later via dashboard.
  • api_key: Required. From Dashboard → API Keys → Create (shown only once)
  • server_endpoint: Required. Your server HTTPS URL, no trailing slash
  • expected_gpu_count: 0 = auto-detect, or set exact count to flag mismatches
4

Test the Agent

Run the agent manually to verify it can collect metrics and reach the server.

sudo -u monitoring-agent /opt/monitoring-agent/venv/bin/python /opt/monitoring-agent/run.py

Expected output (JSON logs):

{"ts":"2026-06-01T17:35:04","level":"INFO","module":"main","msg":"Starting collection for rig a1b2c3d4-..."}
{"ts":"2026-06-01T17:35:06","level":"INFO","module":"transport","msg":"Ingest response: 200 {\"status\": \"new\"}"}
{"ts":"2026-06-01T17:35:06","level":"INFO","module":"main","msg":"Payload accepted: new"}

The cron job starts automatically within 1 minute. Check /var/log/monitoring-agent/agent.log for ongoing logs.

Next Steps
